# Клиника v0.5 — статический веб-сайт

Интерактивная ночная смена в психиатрической больнице. Чистый фронтенд:
HTML + CSS + ES-модули, без сборщика и без своего бэкенда. Данные и
состояние игры синхронизируются с Firebase прямо из браузера.

## Файлы

```
index.html      разметка, экраны коридора и палаты
style.css       оформление, 4 темы, анимации
app.js          игровая логика: сцены, звук, озвучка, предметы, управление
game-state.js   GameState: сохранение настроек, комнат и прогресса
firebase.js     подключение Firebase, чтение/запись, отказоустойчивость
```

Зависимостей нет. Firebase SDK подключается с CDN
(`https://www.gstatic.com/firebasejs/10.12.2/`).

## Размещение на GitHub Pages

1. Создать репозиторий и загрузить в него пять файлов из корня.
2. **Settings → Pages → Source: Deploy from a branch**, ветка `main`,
   папка `/ (root)`.
3. Через минуту сайт откроется по адресу
   `https://<пользователь>.github.io/<репозиторий>/`.

Локальная проверка (модули требуют http, не file://):

```bash
python -m http.server 8080
```

### Правила доступа

Сейчас действуют правила с ограничением по сроку:

```json
{
  "rules": {
    ".read": "now < 1796763600000",
    ".write": "now < 1796763600000"
  }
}
```

**9 декабря 2026 правила перестанут действовать** — чтение и запись
закроются для всех. После этой даты приложение не сломается: оно
переключится на localStorage и продолжит работать, но синхронизации
между устройствами не будет.

Чтобы продлить или снять ограничение, в консоли Firebase
(https://console.firebase.google.com/project/clinika-1a6cb/database)
открыть раздел Rules и заменить правила. Для открытой игры без
авторизации:

```json
{
  "rules": {
    ".read": true,
    ".write": true
  }
}
```

Для продакшена правила нужно ужесточить — например, разрешить запись
только авторизованным пользователям и ограничить размер данных.

## Структура данных в базе

Настройки, посещённые комнаты и прогресс — **личные** данные, поэтому
лежат под идентификатором устройства. Иначе выключенный кем-то голос
выключался бы у всех. Предметы палат — общие, их видят все, кто в палате.

```
clinica/
├── players/<deviceId>/          личные данные игрока
│   ├── settings/                { sound, voice, theme, reduceMotion, masterVolume }
│   ├── rooms/                   { current, visited: {roomId: count}, unlocked: {} }
│   └── progress/                { heard: {actorId: n}, itemsPlaced, openedDialogs }
└── items/<roomId>/              предметы палаты (общие для всех)
    └── item_abc123/             { url, caption, x, y, scale, fileName, mime, cut, createdAt }
```

Идентификатор устройства создаётся при первом запуске и хранится в
`localStorage` под ключом `clinika.device.v05`.

## Как работает отказоустойчивость

Главное требование: игра никогда не зависает и никогда не теряет
данные, даже если Firebase недоступен.

| Что случилось | Что делает приложение |
|---|---|
| Базы нет в проекте | Проба не проходит → локальный режим, статус «локальный режим» |
| Нет связи с базой | То же: таймаут 4 с, затем локальный режим |
| Правила запрещают запись | Запись отклонена → облако выключается, данные уже в localStorage |
| Связь восстановилась | Автопроверка раз в 30 с → возврат в облачный режим |

Как это устроено:

1. **Проба базы** перед подключением: проверяется живое соединение
   `.info/connected`, право читать и право писать. Проба занимает
   несколько секунд, игра в это время уже доступна.
2. **Каждая операция с базой идёт с таймаутом** (`withTimeout`).
   Firebase SDK при недоступной базе не бросает ошибку, а молчит —
   без таймаута игра зависла бы навсегда.
3. **Запись сначала идёт в localStorage**, и только потом в облако.
   Поэтому при отказе данные не теряются.
4. **Отказ по правам выключает облако целиком**, чтобы не пытаться
   писать в базу снова и снова.
5. **Подписки отписываются** при отключении облака — висящих
   соединений не остаётся.

## Управление

Мышь и клавиатура работают вместе.

| Действие | Мышь | Клавиатура |
|---|---|---|
| Выбрать палату | Клик по карточке | ← → |
| Войти в палату | Клик по карточке | Enter |
| Открыть персонажа | Клик по фигуре | 1…4 |
| Поговорить | Клик по кнопке «Сказать ещё» | — |
| Перетащить предмет | Зажать и тянуть | — |
| Выбрать предмет | Клик | Tab |
| Закрыть панель/диалог | Клик по крестику | Esc |
| Вернуться в коридор | Клик по «← В коридор» | Esc |

## Звук

Атмосферные звуки и дверной скрип генерируются через Web Audio API,
файлов нет.

* **Скрип двери** — три слоя: щелчок замка, скрип с плавающей частотой
  через полосовой фильтр, глухой удар с низким гулом. Каждый раз
  параметры случайные: скорость, громкость, высота фильтра.
* **Фон палаты** — едва слышный гул и редкие потрескивания. Гул всегда
  один: при входе в новую палату предыдущий останавливается, иначе
  звук накапливался бы.
* **Озвучка персонажей** — Web Speech API, язык ru-RU. У каждого
  персонажа свои pitch и rate:

  | Персонаж | pitch | rate |
  |---|---|---|
  | Передозолох | 0.45 | 0.8 |
  | Куклотряпка | 1.15 | 0.9 |
  | Кукла | 0.85 | 0.78 |
  | Перезолош | 0.6 | 0.85 |

Все звуки отключаются в настройках, там же — общая громкость.

## Темы

Четыре оформления палат: классическое, холодное, тёплое, монохром.
Переключаются в панели настроек, применяются мгновенно и сохраняются.

Тема меняет палитру интерфейса и фон сцены палаты.

## Предметы игроков

Игрок может загрузить свою картинку или GIF:

* фон по краям убирается автоматически (для GIF анимация сохраняется);
* у предмета есть подпись (до 80 символов) и масштаб;
* предмет можно перетаскивать мышью;
* предметы палаты видят все, кто в ней находится, — данные идут
  через `clinica/items/<roomId>` с живой подпиской.
